# 95+ Rubric Upgrade Master Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Raise the current submission from an evidence-backed provisional 77.5/100 to an internal 97/100 quality bar within three weeks by making every rubric claim true, traceable, reproducible, and presentation-ready.

**Architecture:** Four coordinated plans deliver independently reviewable layers: pipeline contracts, reproducibility/evidence, the report/model card, and the presentation/reflections. Technical behavior is frozen before the authoritative real-data run; every later document consumes the resulting machine-readable evidence rather than copying numbers by hand.

**Tech Stack:** Python 3.13.9, pandas, Pandera, scikit-learn, XGBoost, MLflow, DVC 3.67.1, Pytest, Make, Docker, GitHub Actions, Markdown, DOCX/PDF, and PowerPoint.

## Global Constraints

- Internal quality target is 97/100; this is a buffer, not a guaranteed academic mark.
- The chronological split is exactly 50% train, 10% model validation, 10% threshold calibration, and three 10% production batches.
- The operating threshold is selected only on the calibration slice; threshold 0.5 is retained only as a named comparison.
- Required-stage validation and MLflow registry failures must fail visibly.
- Monitoring may recommend retraining, but a human must approve any retraining or promotion.
- Python must report version 3.13.9 in development, CI, and Docker verification evidence.
- DVC is pinned exactly to 3.67.1 and is used for lineage, parameters, hashes, metrics, and plots; the repository must not claim a DVC remote stores the 144 MB real CSV.
- The Docker base is `python:3.13.9-slim@sha256:326df678c20c78d465db501563f3492d17c42a4afe33a1f2bf5406a1d56b0e86`.
- The full Pytest suite must pass with zero skips.
- The final technical report must contain 4,000–5,000 rendered words.
- The presentation must run 8–10 minutes, with a target of 9:15–9:40.
- Each of the four reflections must contain 500–800 authentic words; the working target is 550–700.
- Do not add an API, Kubernetes, a feature store, Airflow, microservices, automatic model replacement, or a new model family.
- Do not add SHAP or another explainability package until every rubric-critical gate is complete; discuss it only as future work.
- Do not begin new feature work after Day 18 unless it fixes a submission-blocking defect.
- Preserve the existing untracked `MLOpsMaster_Final_Project_Briefing_Credit_Card_Fraud.docx` and `data.zip`.
- Do not push, create a pull request, publish a release, or submit university files without explicit user approval.
